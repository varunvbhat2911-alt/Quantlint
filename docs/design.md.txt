# QuantLint Design System

Version: 1.0

Status: Active

Last Updated: August 2026

---

# Purpose

This document defines the complete design language of QuantLint.

Every page, component, animation, spacing rule, and interaction should follow this design system.

The goal is to make QuantLint feel like a professional SaaS product rather than a collection of unrelated pages.

Every AI coding assistant must follow this document when building UI.

---

# Design Philosophy

QuantLint is professional software built for developers, traders, and quantitative researchers.

The interface should communicate

- Trust
- Precision
- Clarity
- Simplicity
- Performance

The UI should never feel playful.

The UI should never feel cluttered.

The UI should prioritize information over decoration.

# Core Principles

Every screen should follow these principles.

---

## Simplicity

Every element should have a purpose.

Remove unnecessary visual noise.

Prefer whitespace over separators.

---

## Consistency

Buttons should always behave the same.

Cards should always have the same spacing.

Forms should always follow the same layout.

Navigation should remain identical across the application.

---

## Readability

Typography should always be easy to scan.

Avoid long paragraphs.

Use hierarchy.

Headings

↓

Subheadings

↓

Body

↓

Caption

---

## Accessibility

Support keyboard navigation.

Maintain sufficient color contrast.

Use semantic HTML.

Every icon button must have an accessible label.

---

## Responsiveness

Desktop is the primary experience.

Tablet should be fully supported.

Mobile should remain usable.

No horizontal scrolling.

Use consistent page padding.

# Component Design System

Every UI component should follow the same visual language.

Components should always be reusable.

Never build page-specific buttons, cards, or forms unless absolutely necessary.

---

# Buttons

Buttons communicate importance through hierarchy.

Only four button variants should exist.

## Primary Button

Purpose

Primary actions.

Examples

- Analyze Strategy
- Create Project
- Save Changes
- Generate Report

Style

- Filled
- Primary color
- Medium shadow
- Rounded corners

Only one primary button should exist in a section.

---

## Secondary Button

Purpose

Alternative actions.

Examples

- Cancel
- Back
- Edit

Style

- Outline
- Neutral colors

---

## Ghost Button

Purpose

Low emphasis actions.

Examples

- Close
- More
- Open Menu

No border.

Transparent background.

---

## Destructive Button

Purpose

Dangerous actions.

Examples

- Delete Project
- Remove Strategy
- Reset Settings

Always use danger colors.

Never reuse destructive styling for normal actions.

# User Experience Principles

Users should never lose their work.

Long-running tasks should continue in the background.

Always communicate progress.

Avoid unexpected page reloads.

Avoid modal overload.

Prefer dedicated pages for complex workflows.

Every important action should provide immediate feedback.

Every destructive action must require confirmation.

# Final Design Principle

The interface should make complex quantitative analysis feel approachable.

Users should spend their time understanding strategies, not understanding the interface.

Every screen should reduce cognitive load while increasing confidence in the analysis.

When in doubt,

choose clarity over creativity.

---

# Visual Identity

QuantLint should feel like software used inside a hedge fund.

The interface should resemble

- Linear
- Apple
- Stripe Dashboard
- Arc Browser
- Mercury
- Vercel

Avoid startup clichés.

Avoid glowing gradients.

Avoid neon colors.

Avoid excessive borders.

Avoid large colorful cards.

The interface should feel

- Quiet
- Expensive
- Premium
- Minimal
- Confident

The UI should rely on

- whitespace
- typography
- subtle elevation
- motion

instead of colors.
