# QuantLint Development Memory

Version: 1.0

Status: Active

Last Updated: August 2026

---

# Purpose

This document serves as the long-term memory of the QuantLint project.

Unlike progress.md, which only reflects the current project status, memory.md records the complete development history.

Every significant implementation, architectural decision, challenge, and lesson learned should be recorded here.

This document allows future contributors and AI coding assistants to quickly understand how the project has evolved over time.

Nothing should be deleted from this document.

New sessions should always be appended to the end.

---

# How To Use This Document

Every development session should create one new entry.

Each entry should include

- Date
- Session Number
- Goal
- Completed Work
- Decisions Made
- Problems Encountered
- Solutions Applied
- Lessons Learned
- Next Session Goal

Do not rewrite previous entries.

Append only.

## Session 1

Date

August 2026

---

Goal

Initialize Next.js 15 frontend foundation project with TypeScript, Tailwind CSS, shadcn/ui, theme provider, and architecture folder structure.

---

Completed Work

- Initialized Next.js 15 App Router project.
- Configured TypeScript (`tsconfig.json`) and path alias `@/* -> ./src/*`.
- Configured Tailwind CSS v4 & custom CSS variables for dark/light themes.
- Configured shadcn/ui (`components.json`) and `cn()` utility (`src/lib/utils.ts`).
- Installed core dependencies (`zustand`, `@tanstack/react-query`, `lucide-react`, `next-themes`, `recharts`, `clsx`, `tailwind-merge`, `class-variance-authority`).
- Installed dev dependencies (`prettier`, `eslint-config-prettier`, `eslint-plugin-prettier`).
- Created feature-first folder structure per `architecture.md` (`components/ui`, `components/layout`, `components/common`, `components/charts`, `features/auth`, `features/projects`, `features/strategies`, `features/analysis`, `features/reports`, `hooks`, `services`, `store`, `types`, `styles`, `constants`).
- Configured `Inter` and `JetBrains Mono` fonts via `next/font/google`.
- Configured Dark/Light/System theme provider (`ThemeProvider` & `ThemeToggle`).
- Configured ESLint and Prettier (`.prettierrc`, `.prettierignore`).
- Created clean root layout and minimal placeholder page with theme toggle.

---

Major Decisions

- Set dark mode as the default application theme (`defaultTheme="dark"`).
- Configured `Inter` as the primary UI font and `JetBrains Mono` as the code font.
- Used `React.useSyncExternalStore` for the `ThemeToggle` component to guarantee hydration safety without effect state warnings.

---

Challenges

- React 19 / ESLint hook check flagged synchronous `setMounted(true)` inside `useEffect`.
- Resolved by utilizing `React.useSyncExternalStore` for hydration-safe client mounting check.

---

Lessons Learned

- `useSyncExternalStore` is cleaner and zero-re-render for handling SSR client mounting state than `useEffect` + `useState`.

---

Testing

- `npm run lint`: Passed (0 errors, 0 warnings)
- `npm run build`: Passed cleanly

# Memory Guidelines

Every future session should follow the same structure.

Avoid recording trivial details.

Examples of information worth recording

- Architectural decisions
- New modules
- Bugs that required investigation
- Performance improvements
- Refactoring decisions
- Security improvements
- AI prompt improvements
- Major UI redesigns

Avoid recording

- Minor CSS tweaks
- Typo fixes
- Small formatting changes
- Routine dependency updates

---

# Important Project Decisions

These decisions should remain visible throughout the project's lifetime.

- Build for long-term scalability.
- Keep AI provider agnostic.
- Never execute uploaded strategy code.
- Never use AI for deterministic financial calculations.
- Build documentation alongside code.
- Keep commits small and focused.
- Maintain clean architecture at all times.
- Prioritize maintainability over speed.

---

# Memory Maintenance Rules

At the end of every coding session

1. Append a new session.

2. Never edit historical entries unless correcting factual mistakes.

3. Record major implementation decisions.

4. Record unresolved issues.

5. Record improvements made.

6. Define the objective for the next session.

7. Update progress.md separately.

memory.md is historical.

progress.md is current.

Do not mix their responsibilities.

# Common Mistakes To Avoid

Never

- Execute uploaded Python code.
- Store API keys in source code.
- Skip documentation updates.
- Mix business logic into UI.
- Modify unrelated files.
- Introduce breaking changes without updating documentation.
- Hardcode environment-specific values.

Always

- Keep prompts focused.
- Commit after every completed task.
- Update progress.md.
- Append memory.md.
- Follow architecture.md.
- Follow design.md.
- Follow rules.md.
